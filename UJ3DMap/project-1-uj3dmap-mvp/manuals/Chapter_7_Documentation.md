## Section 1: JSDoc Annotation Standards & AST Analysis

### Architecture and State Diagrams

```mermaid
graph TD
    Source[Vanilla JS File] --> Comment[/** @param {string} id */]
    Comment --> TSServer[TSServer AST Parser]
    TSServer --> Inference[Infer Type Boundaries]
    Inference --> IDE[VSCode Intellisense Hover]
    Inference --> CLI[jsdoc CLI Compiler]
    CLI --> HTML[Generate api-docs.html]
```

### Step-by-Step Implementation Instructions

1. **Enforce Block Syntax**: JSDoc commands are strictly parsed only when utilizing the double-asterisk block format `/** ... */`. Standard `/* */` or `//` comments are ignored by the AST parser.
2. **Define Parameters**: Utilize `@param {Type} name - Description` for every function argument.
3. **Define Returns**: Utilize `@returns {Type} Description` for outputs.
4. **Define Exceptions**: Utilize `@throws {ErrorType} Description` to warn downstream implementers of `try/catch` requirements.

### Code Blocks and Analysis

#### Code Block 1.1: `src/data/api.js` (Documentation Injection)
```javascript

 * @throws {Error} Throws if HTTP status is non-2xx.
 * @throws {DOMException} Throws 'AbortError' if the timeoutMs threshold is exceeded.
 */
export async function fetchWithTimeout(endpoint, timeoutMs = 8000) {
  // Implementation...
}
```

#### Table 1.1: 5W1H+Which Analysis for Code Block 1.1
| Line | What | When | Why | Where | How | Which |
|---|---|---|---|---|---|---|
| `/**` | Parser Trigger | IDE Parsing | Instructs the TypeScript Language server that the following block contains AST-valid type instructions | Pre-Function | Double Asterisk | Block initiation |
| `@async` | Event Loop Hint | IDE Parsing | Explicitly marks the function as returning a Promise, aiding autocomplete engines | JSDoc Block | Keyword Tag | Async declaration |
| `@param {string}` | Type Assertion | IDE Parsing | Forces the IDE to throw a squiggly-line error if a developer passes an integer to the function | JSDoc Block | Bracket Notation| Type guard |
| `[timeoutMs=8000]`| Optional Parameter| IDE Parsing | Bracket notation informs the compiler that the argument is not required for execution | JSDoc Block | Bracket syntax | Argument config |
| `Promise<Object>` | Generic Typing | IDE Parsing | Indicates the asynchronous wrapper resolves to a specific memory structure (an Object, not a scalar) | JSDoc Block | Generic syntax | Return typing |
| `@throws` | Exception Warning | IDE Parsing | Maps required error boundaries, forcing developers to implement `catch` blocks | JSDoc Block | Keyword Tag | Error definition |

## Section 2: Advanced Type Definitions (@typedef)

### Architecture and State Diagrams

```mermaid
graph LR
    TypeDef[@typedef {Object} GeoNode] --> Property1[@property {string} id]
    TypeDef --> Property2[@property {Array<number>} coordinates]
    Property1 --> Usage[@param {GeoNode} node]
    Property2 --> Usage
    Usage --> TSServer[Type Validation]
```

### Step-by-Step Implementation Instructions

1. **Construct Type Definitions**: For complex payloads like GeoJSON features or Graph Nodes, utilize `@typedef` to define a reusable custom shape.
2. **Assign Properties**: Use `@property {Type} name` to define internal keys.
3. **Reference the Type**: Utilize the new type name in downstream `@param` declarations.

## Section 3: Automated API HTML Generation

### Step-by-Step Implementation Instructions

1. **Install Compiler**: Execute `npm install -D jsdoc`.
2. **Configure Engine**: Create `jsdoc.json` to instruct the compiler on recursive directory scanning and output parameters.
3. **Bind NPM Script**: Add `"docs": "jsdoc -c jsdoc.json"` to `package.json`.

### Code Blocks and Analysis

#### Code Block 3.1: `jsdoc.json`
```json
{
  "source": {
    "include": ["src"],
    "includePattern": ".+\\.js(doc|x)?$",
    "excludePattern": "(^|\\/|\\\\)_"
  },
  "opts": {
    "destination": "./docs",
    "recurse": true,
    "readme": "README.md",
    "template": "templates/default"
  }
}
```

#### Table 3.1: 5W1H+Which Analysis for Code Block 3.1
| Line | What | When | Why | Where | How | Which |
|---|---|---|---|---|---|---|
| `"include": ["src"]` | AST Scan Target | `npm run docs` | Instructs the CLI to only parse application logic, ignoring `node_modules` or config files | `source` block | Array | Target directory |
| `"excludePattern"` | Ignored Files | `npm run docs` | Prevents parsing of hidden or internal files prefixed with underscores | `source` block | Regex String | Exclusion rule |
| `"destination": "./docs"`| Render Output | `npm run docs` | Defines the local filesystem path where the static HTML files will be deposited | `opts` block | String Path | Output directory |
| `"recurse": true` | Directory Traversal| `npm run docs` | Forces the parser to evaluate `src/data`, `src/routing`, etc., rather than stopping at the root | `opts` block | Boolean flag | Traversal depth |

## Section 5: Troubleshooting & Edge Case Diagnostics

| Symptom / Issue | Root Cause | V8 / Browser Mechanics | Exact Resolution |
|-----------------|------------|------------------------|------------------|
| **IDE fails to show autocomplete**| Syntax Error | Single asterisk `/*` used instead of double `/**`. The TSServer ignores standard block comments to save CPU cycles. | Ensure all documentation blocks begin strictly with `/**`. |
| **`jsdoc` throws FATAL error** | ES6 Module Conflict| Older `jsdoc` versions occasionally fail to parse modern `import/export` syntax natively. | Ensure JSDoc version is latest (`>4.0.0`) which incorporates modern ES6 AST parsing. |
| **Type mismatch warning in IDE** | Drifted Documentation| The codebase evolved (e.g. timeout changed to integer) but the `@param {string}` was not updated. | Manually sync JSDoc blocks with physical function signatures. |
